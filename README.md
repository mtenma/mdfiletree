# MDFileTree

表の再現性を重視した、macOS 向けの Markdown リーダーです。Tauri v2 で作っています。

一般的な Markdown ビューアは GFM のパイプ表しか扱えず、結合セルや複数行セルを含む表が崩れます。
MDFileTree は MultiMarkdown の拡張表構文と生 HTML の表を両方そのまま通し、書いたとおりに読めることを目指しています。

## 画面

```
┌──────────────────────────────────────────────┐
│ ‹ ›  📂 📄  ファイル名        🔍 A- A A+ ⤓ ⎙ ☀ │
├──────────┬───────────┬───────────────────────┤
│ フォルダ │ 目次      │ 本文                  │
│ ツリー   │ (追従)    │                       │
├──────────┴───────────┴───────────────────────┤
│ パス                    見出し数 サイズ 更新 │
└──────────────────────────────────────────────┘
```

## 対応している記法

### 表

| 記法 | 例 |
| --- | --- |
| GFM パイプ表・列の寄せ | `\| :--- \| :---: \| ---: \|` |
| 列の結合 | 行末のパイプを重ねる `\| 内容 \|\|` |
| 行の結合 | `^^` で上のセルと結合 |
| 複数行のセル | 行末のバックスラッシュで継続 |
| キャプション | 表の直後に `[説明文]` |
| ヘッダーのない表 | 区切り行から始める |
| 本体の分割 | 表の途中に空行を入れる |
| 生 HTML の表 | `colspan` `rowspan` `colgroup` `tfoot` そのまま |

表示面では、枠に収まらない表だけを横スクロール領域にし、収まる表は見出し行をページ基準で固定します。
入れ子のスクロールを作らないので、長い表でも普通に読み進められます。

### そのほか

見出し・リスト・引用・定義リスト・タスクリスト・脚注・略語・絵文字・打ち消し・
ハイライト（`==`）・下線（`++`）・上下付き（`^` `~`）・GitHub 形式の注意書き（`> [!NOTE]`）・
front matter（YAML）・コードの色分け（Shiki）・数式（KaTeX）・作図（Mermaid）。

見出しには `## 見出し {#anchor}` で任意の id を付けられます。

> [!NOTE]
> `markdown-it-attrs`（`{.class}` などの汎用属性記法）は入れていません。
> あの plugin は表の列数を数え直して余分なセルを隠すため、
> MultiMarkdown の結合セルと衝突して表が壊れます。表の再現を優先しました。

## 操作

| 操作 | ショートカット |
| --- | --- |
| フォルダを開く | ⇧⌘O |
| ファイルを開く | ⌘O |
| 文書内を検索 / 次へ / 前へ | ⌘F / ⌘G / ⇧⌘G |
| フォルダツリーの表示切り替え | ⌘\ |
| 目次の表示切り替え | ⌥⌘\ |
| 拡大 / 縮小 / 実際のサイズ | ⌘+ / ⌘- / ⌘0 |
| ライト・ダーク切り替え | ⇧⌘L |
| 戻る / 進む | ⌘[ / ⌘] |
| HTML として書き出す | ⌘E |
| プリント（PDF 保存） | ⌘P |
| Finder で表示 | ⌥⌘R |

本文は Page Up / Page Down / Space / ↑ ↓ / Home / End でもスクロールできます。

ウィンドウにファイルやフォルダをドラッグしても開けます。Finder の「このアプリケーションで開く」にも対応しています。

Finder から開いたファイルは、ファイルごとに新しいウィンドウで表示します。
すでに開いているファイルを開き直したときは、ウィンドウを増やさずそのウィンドウを前に出します。
アプリ内でツリーから選んだり ⌘O で開いたりした場合は、そのウィンドウの表示を差し替えます。

## 動作

- 開いているファイルが更新されると自動で読み直します。読んでいた位置は保持されます
- 相対パスの画像は asset プロトコル経由で表示します
- 本文中のリンクは、外部 URL は既定のブラウザ、`#anchor` は文書内移動、
  相対パスの `.md` はアプリ内で開き、それ以外のファイルは Finder で表示します
- 文書内検索は CSS Custom Highlight API を使い、DOM を書き換えません。
  Mermaid や KaTeX の描画結果を壊さずにハイライトできます

## 開発

```sh
pnpm install
pnpm tauri dev          # 開発起動
pnpm typecheck          # 型チェック
pnpm tauri build        # .app と .dmg を生成
```

Rust 側は `cargo check --manifest-path src-tauri/Cargo.toml` で確認します
（`cargo clippy` を使う場合は `rustup component add clippy` が必要です）。

macOS から Windows 向けにクロスコンパイルすることはできません
（`tauri-winres` が Windows のリソースコンパイラを必要とします）。
Windows 版は GitHub Actions の `windows-latest` で組み立てています。

`samples/` に確認用の Markdown を置いています。

- `tables.md` — 表の全パターン（結合・複数行・キャプション・生 HTML・横に長い表・縦に長い表）
- `kitchen-sink.md` — 表以外の記法をひととおり

## つくり

```
src/
├─ markdown/     レンダリング一式
│   ├─ renderer.ts   markdown-it とプラグインの組み立て
│   ├─ sanitize.ts   DOMPurify の設定（表の属性は通す）
│   ├─ dom.ts        描画後の DOM 処理（画像・リンク・見出し id・表の計測）
│   ├─ highlight.ts  Shiki（画面に入ったブロックから順に着色）
│   └─ mermaid.ts    作図（テーマに追従）
├─ components/   3 ペインの UI
├─ hooks/        文書内検索
└─ lib/          Rust コマンドのラッパ・設定の保存・HTML 書き出し

src-tauri/src/
├─ commands.rs   ファイル読み込み・書き出し・印刷・Finder 表示
├─ tree.rs       フォルダ走査
├─ watcher.rs    ファイル監視（ウィンドウごと・250ms でまとめて通知）
├─ window.rs     ウィンドウの生成と、渡されたパスの振り分け
└─ menu.rs       ネイティブメニュー
```

描画は次の順で処理します。

```
.md → front matter 分離 → markdown-it → DOMPurify → DOM 挿入
                                              → Shiki / Mermaid / 画像 / 目次
```

Shiki を無害化の**後**に置いているのは、DOMPurify が Shiki の CSS 変数を落としかねないためです。
配布された `.md` を開くこともあるので、無害化そのものは外せません
（webview 内のスクリプトはアプリのコマンドを呼べてしまいます）。

## 制限

- macOS で動作を確認しています。Windows 向けのコードは入れてありますが、実機での確認はこれからです
- 署名・公証をしていないため、配布した `.app` は初回に Gatekeeper の警告が出ます
- 文書内検索は、複数の要素にまたがった語（`a<b>bc</b>` の "abc" など）は見つけられません
